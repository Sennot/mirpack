# Spout2 Clean Feed

Geode-мод для Geometry Dash на Windows. В окне игры он показывает хитбоксы и две прогнозируемые траектории, а через Spout2 отправляет в OBS чистый кадр уровня без этих оверлеев.

## Как это работает

- Мод создаёт один общий корневой узел для своих хитбоксов и траекторий.
- Обычный кадр Geometry Dash рисуется без корневого узла оверлеев.
- Перед настоящим `swapBuffers` чистый backbuffer копируется в GPU-текстуру и отправляется в Spout2.
- Сразу после отправки корневой узел хитбоксов и траекторий вручную дорисовывается только на экран игрока.
- В Spout попадает остальная сцена: интерфейс уровня, индикаторы, пауза, меню паузы и редактор. Исключение — интерфейс xDBot, если включён его отдельный фильтр.
- Spout-хук выполняется после `absolllute.hackmega` / `absolllute.megahack`, поэтому отрисованный Mega Hack попадает в OBS до фактического обмена буферов.
- Sender активен во всех сценах, включая главное меню; хитбоксы и траектории привязаны к уровню или редактору.

Spout2 SDK 2.007.017 собирается статически прямо в DLL мода. Отдельные `Spout.dll` или файлы SDK рядом с модом не нужны.

## OBS

1. Установите в OBS совместимый источник-приёмник Spout2.
2. Запустите уровень или редактор Geometry Dash.
3. Добавьте Spout2 Capture Source и выберите sender `Geometry Dash Clean Feed`.
4. При необходимости измените имя sender в настройках мода Geode.

OBS-плагин-приёмник не входит в мод: он устанавливается отдельно в OBS.

## Настройки

Можно отдельно включать хитбоксы и траекторию, выбирать цвета и толщину линий, прозрачность заливки хитбоксов, длину прогнозирования и частоту симуляции. По умолчанию траектория рассчитывает 2 секунды будущего при 240 TPS. Режим `High-performance trajectory` переиспользует память снимков между кадрами; его можно выключить для возврата к пути выделения памяти v1.4.2.

По умолчанию `F3` переключает хитбоксы, а `F4` — траекторию. Оба бинда переназначаются в настройках мода Geode и срабатывают только внутри уровня или редактора.

Отключение применяется на следующем отрисованном кадре, в том числе во время смерти и паузы, когда игровые обновления могут остановиться. Смерть сама по себе не меняет выбранные настройки.

В v1.6.6 проверка остановленного редактора применяется только к текущему игровому слою. Оставшийся в памяти редактор больше не отключает траекторию обычного уровня. Поведение редактирования и плейтеста, физика и параметры прогнозирования не меняются.

Настройки и преобразованные RGBA-цвета кэшируются и обновляются по событию изменения, включая бинды и применение Smart Contrast. Имя Spout не копируется каждый кадр. Симуляция прекращает пустые проходы после завершения всех активных игроков; количество физических шагов, проверки столкновений и длина прогноза сохраняются.

### xDBot только на экране игрока

`Hide xDBot UI in Spout` включён по умолчанию. Фильтр распознаёт узлы с префиксом `zilko.xdbot/` и собственные классы интерфейса из `zilko.xdbot.dll`. Проверены имя пакета `zilko.xdbot.geode` и структура установленной версии xDBot 2.7.7; другие версии требуют проверки в игре.

Меню, кнопки и индикаторы xDBot дорисовываются локально после захвата Spout. Сцена уровня не рисуется повторно, контейнеры игровых объектов не обходятся. Настройки записи/воспроизведения макросов, физика и прогнозирование не меняются. Mega Hack по-прежнему попадает в Spout.

В v1.6.5 фильтр больше не вставляет служебные узлы в сцены и не сортирует их дочерние элементы. Отбор интерфейса выполняется после обновлений планировщика и после переключения сцены; на паузе директора — перед отрисовкой. Перед следующим обновлением, сменой сцены и при пропуске отправки кадра временная видимость восстанавливается. Это устраняет вмешательство v1.6.4 в первый дочерний элемент сцены, на который могут рассчитывать меню игры и другие моды.

Обход ограничен 4096 узлами и глубиной 64 на кадр. При превышении лимита он отменяет скрытие целиком: в таком кадре xDBot может попасть в Spout, зато фильтр не продолжает неограниченный обход необычного интерфейса. Контейнеры объектов уровня в лимит не входят, так как их содержимое вообще не просматривается.

Фильтр не скрывает универсальные диалоги Geode, чужие окна с вложенными настройками xDBot и изменения самой картинки уровня, например layout mode. Локально отложенный интерфейс рисуется поверх остальных элементов: при одновременно открытых окнах их перекрытие может отличаться. Фильтр можно выключить без перезапуска.

### Smart Contrast

Кнопка `Analyze` в настройках открывает список скачанных и редакторских уровней, данные которых сохранены локально. Анализ идёт в фоновом потоке с прогресс-баром и создаёт три палитры: Balanced, Comfort и Maximum.

Результат кэшируется по хэшу строки уровня. Выбор палитры меняет только уже существующие RGB-настройки хитбоксов, игрока и траектории; логика их рисования и расчёта не меняется. После завершения worker полностью заканчивает работу и не создаёт нагрузку в кадре.

Анализатор учитывает копирование цветовых каналов, HSV-сдвиги, цвета Color/Pulse-триггеров и масштаб объектов. Это оценка по данным уровня, а не покадровое воспроизведение всех его эффектов.

## Сборка

После push или pull request workflow `.github/workflows/build.yml` собирает Win64 `.geode` и PDB и публикует их как GitHub Actions artifact.

Для локальной сборки нужны Visual Studio 2022, CMake, Ninja и Geode SDK:

```powershell
$env:GEODE_SDK = "C:\path\to\geode"
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
```

Регрессионные тесты биндов, кэша настроек и отбора интерфейса запускаются без игры и SDK:

```powershell
cmake -S tests -B build/unit
cmake --build build/unit --config Release
ctest --test-dir build/unit -C Release --output-on-failure
```

Они проверяют отключение оверлеев без игровых обновлений, независимость двух биндов, повторы клавиш, загрузку сохранённых значений и смену палитр. Ручная проверка в игре: переключить F3/F4 во время смерти и паузы, возобновить игру, затем выйти из редактора и снова открыть уровень.

Отдельный тест траектории проверяет оставшийся в памяти редактор, отсутствие редактора, несовпадающие слои и последовательность редактирование → плейтест → пауза → остановка → обычный уровень. Состояние постороннего редактора не читается. Ручная проверка: с включённой траекторией открыть редактор, запустить и остановить плейтест, выйти и запустить обычный уровень; траектория должна снова отображаться без перезапуска игры.

Тест отбора интерфейса проверяет изоляцию xDBot, сохранение скрытых элементов, неизменность порядка и первого элемента сцены, ограничение больших/зацикленных деревьев, отмену частичного скрытия и пропуск контейнеров со 100 000 объектами. Для проверки реального рендера нужно сравнить OBS и окно игры с открытым меню xDBot, его индикаторами, паузой, редактором и переходами между сценами; затем выключить фильтр и убедиться, что интерфейс снова попадает в OBS. Отдельно открыть поиск и сохранённые уровни, пролистать список, вернуться назад и повторить с включённым и выключенным фильтром.
